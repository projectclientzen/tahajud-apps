# Brief T1 (Agen A, Sonnet, effort high): auth, onboarding, logout, sambungan offline

Baca: `CLAUDE.md`, `docs/briefs/PARALLEL-RULES.md`, `docs/PLAN.md` (baris T1), PRD v1.2.3 §5.2, §6.1, §6.2, §6.4, §21.4, §24.1 (bagian batas perangkat), `docs/sessions/S4a.md` (API antrean, auth layer, PWA), `docs/sessions/S3.md`.

## Tugas
1. Layar `/login` (email), `/auth/verify` (OTP 6 digit, input numerik, paste kode, kirim ulang setelah 60 detik, "Tidak menerima kode?" berisi cek spam, cek email checkout Scalev, tombol WhatsApp CS dengan nomor dari env `NEXT_PUBLIC_CS_WHATSAPP`, kosong = tombol disembunyikan), `/access-status` (purchase pending, no active access, session expired). Respons UI identik untuk email terdaftar dan tidak.
2. Batas 3 perangkat (keputusan owner, PRD §24.1): ubah `src/domain/auth/devices.ts` dan mock auth. Login ke-4 setelah OTP benar menghasilkan status `device_limit` + daftar perangkat + token login tertunda (10 menit, sekali pakai). Layar: "Akunmu sudah aktif di 3 perangkat (maksimal)", pilih satu perangkat untuk dikeluarkan lalu lanjut, atau batal. Hapus logika pengeluaran otomatis. Test unit + e2e.
3. Onboarding: jalur minimum (welcome → wilayah atau jadwal manual → konfirmasi Subuh → dashboard, ≤ 3 layar sebelum dashboard), langkah opsional (3 level, target tidur, notifikasi, install PWA) bisa dilewati dan muncul sebagai kartu setup di dashboard. Panggil `requestPersistentStorage()`. `profile.setLocation` lalu `profile.completeOnboarding`.
4. Guard route: belum login → `/login`; login tanpa entitlement → `/access-status`; belum onboarding → `/onboarding`; `/` mengarahkan user login ke `/dashboard`. Mode demo tetap bisa dibuka lewat dev panel.
5. Sambungkan antrean offline S4a: `DataProvider` membuat `OfflineQueue` per user, counter memakai antrean (hapus `TODO(S4a)`), indikator "Tersimpan di perangkat / Tersinkron" membaca antrean.
6. Logout: menu di shell; dialog bila `canLogoutSafely()` false ("Ada X catatan belum tersinkron": Sinkronkan dulu / Keluar dan buang, konfirmasi kedua); tampilkan item `rejected`; `purgeUser` setelah keluar.
7. Penempatan PWA: `UpdatePrompt` di shell, `InstallGuide` di onboarding opsional dan kartu dashboard.
8. Header dashboard: ikon notifikasi (link `/notifications`) dan profil sesuai PRD §8.2 A.

## Acceptance criteria
AUTH-06 (UI identik, rate limit tampil sebagai pesan ramah), AUTH-07 (e2e: OTP diketik, tanpa navigasi keluar), batas perangkat (e2e: perangkat ke-4 ditolak, keluarkan satu, login lanjut), DZIKIR-02 (e2e: offline → 30 tap → online → server 30, tanpa dobel), DZIKIR-06 (e2e dialog), SECURITY-06 (e2e: IndexedDB `tahajud-<userId>` hilang setelah logout), onboarding ≤ 3 layar (e2e menghitung langkah), `grep -r "TODO(S4a)" src` kosong, axe 0 serious/critical light+dark di semua route baru, gerbang verifikasi standar di `docs/PLAN.md`.
