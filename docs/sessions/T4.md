## Temuan penting untuk owner dan orchestrator
Format `txt-2` Tanzil menaruh basmalah di depan teks ayat 1 setiap surah (kecuali Al-Fatihah dan At-Taubah). Contoh: `18|1|بِسْمِ ... ٱلرَّحِيمِ ٱلْحَمْدُ لِلَّهِ ...`. Efeknya:
- Surah 18, 36, 55, 56, 67 ayat 1 mengandung basmalah di awal. 65:2-3 tidak terpengaruh.
- Teks tidak saya ubah (aturan byte-per-byte). Reader tidak boleh memotong string secara diam-diam.
- Opsi: (a) tampilkan apa adanya (basmalah tampil sebagai bagian ayat 1), atau (b) owner menyetujui aturan eksplisit di Reader/dataset untuk memisahkan basmalah dari ayat 1, dengan test yang membuktikan potongan + sisa = teks asli. Perlu keputusan owner. [Medium confidence soal perilaku format: terlihat langsung di file; belum dicek ke dokumentasi Tanzil.]

## Keputusan teknis
1. `web-push@4.0.0` ditambah (VAPID + enkripsi payload RFC 8291 sudah teruji; menulis sendiri berisiko). `@types/web-push@3.6.4` ditambah karena v4 tidak membawa tipe. Typecheck lolos dengan named import. `pnpm audit --prod` bersih.
2. Script berjalan dengan `node --experimental-strip-types` (Node 22), tanpa dependency `tsx`. Satu file, tanpa import lokal.
3. Script default memakai file sumber yang sudah ada dan gagal jika checksum berbeda dari SOURCE.md. `--refresh` mengunduh ulang dan memberi peringatan jika checksum berubah (owner harus setuju).
4. Label sumber jadwal: `provider` (fetch baru atau cache bulan yang masih berlaku), `cached` (provider gagal, cache valid dipakai, label UI "Jadwal tersimpan"), `manual`. Tanggal tanpa data valid memunculkan `SCHEDULE_UNAVAILABLE`, tidak pernah tampil sebagai jadwal terverifikasi.
5. Prefetch bulan berikutnya jika sisa validitas <= 7 hari (best effort, PRD 14.4).
6. Push: TTL default 900 detik (batas terpendek-menengah di PRD 15.1; scheduler T6 bisa override per tipe). Retry 429/5xx/network error, 3 percobaan, backoff 1s, 2s. 404/410 mengembalikan `deactivate` tanpa retry. Sender tidak menyentuh DB: pemanggil (T6) yang menonaktifkan subscription dan mengisi `failure_count`.
7. URL payload wajib path relatif (`/...`, bukan `//`), field payload di-whitelist.
8. Kunci VAPID dev dibuat oleh test dan sertifikat TLS self-signed dibuat via `openssl` ke direktori temp (dihapus setelah test). Tidak ada secret di repo.
