## Yang dikerjakan (nomor brief)

1. **Login, OTP, access-status.** Email, lalu kode 6 digit di app (`inputmode=numeric`, `autocomplete=one-time-code`, paste "123 456" jalan, kirim otomatis di digit ke-6). Email disimpan di `sessionStorage` tab ini, bukan URL. Kirim ulang aktif setelah 60 detik. "Tidak menerima kode?" berisi cek spam, cek email checkout Scalev, tombol kirim ulang, tombol WhatsApp CS. Rate limit tampil sebagai "Coba lagi dalam N menit/detik". Permintaan saat cooldown 60 detik langsung membuka layar kode (tidak buntu). Layar `/access-status` dipilih dari jawaban server, bukan dari URL.
2. **Batas 3 perangkat.** `devicesToRevoke` dihapus. Verifikasi ke-4 mengembalikan `status: "device_limit"` + daftar perangkat + token tertunda. Layar "Akunmu sudah aktif di 3 perangkat (maksimal)". Kontrak baru: `VerifyOtpResult`, `completePendingLogin`, kode error `PENDING_LOGIN_INVALID`.
3. **Onboarding.** Welcome, wilayah (atau jadwal manual), konfirmasi Subuh, dashboard. Tepat 3 layar ("Langkah x dari 3"). `requestPersistentStorage()` dipanggil saat konfirmasi, lalu `profile.setLocation`, `profile.completeOnboarding`. Langkah tambahan di `/onboarding/extra` (tiga level, target tidur, pengingat, panduan pasang), semuanya bisa dilewati.
4. **Guard.** `(app)/layout.tsx` memakai `AppGate`. `/` dan `/login` mengarahkan user yang sudah masuk ke `/dashboard`.
5. **Antrean.** `DataProvider` membuat `OfflineQueue` per user + `bindQueueTriggers`. Counter: tap, flush 2 detik oleh reducer, lalu `enqueue`. Hitungan di layar = server + catatan di antrean + tap belum disimpan, jadi reload saat offline tetap menampilkan hitungan benar. Jawaban server diterima lewat `subscribeAcks`.
6. **Logout.** `LogoutButton` di sidebar (desktop) dan header (mobile). Antrean kosong: satu konfirmasi. Ada catatan: "Ada X catatan belum tersinkron", Sinkronkan dulu / Keluar dan buang (konfirmasi kedua). Item `rejected` ditampilkan dengan alasan. Urutan: `queue.close()`, `auth.logout()`, `purgeUser`.
7. **PWA.** `UpdatePrompt` di `AppShell`. `InstallGuide` di onboarding dan di kartu dashboard.
8. **Header dashboard.** Ikon notifikasi (`/notifications`, dibuat T2) dan profil.

## Belum diuji / risiko

- Safari iOS, Firefox: tidak diuji. OTP `autocomplete=one-time-code` di iOS belum dicoba.
- Checklist amalan belum lewat antrean (masih langsung ke data layer). Offline, centang gagal dengan pesan data layer. Tipe `checklist_set` di antrean sudah siap.
- Dua tab pada user yang sama bisa mengirim catatan yang sama. Aman (server dedupe), belum diuji.
- `/notifications`, `/settings`, `/profile` dibuat T2. Kartu "Atur wilayah salat" menautkan `/settings`, ikon header ke `/notifications`. Di branch ini tautan itu 404 sampai T2 di-merge.
- First Load JS `/dashboard` 198 kB (angka Next) dan `/` naik dari 103 ke 156 kB karena provider auth/data di root. T8 menargetkan ≤ 200 KB gzip per route: perlu diukur ulang.
- Aksi `Keluar` memanggil `auth.logout()` lalu menghapus database walau server gagal dijangkau (logout lokal tetap jalan).
- Mode live: `createAuthLayer` stub menolak. `AppGate` menampilkan "Belum bisa memeriksa akunmu", layar login menampilkan pesan umum "Kode belum bisa dikirim".
