## Yang dikerjakan

1. `AuthProvider` (di root layout) dan `DataProvider` per user yang membuat layer data, `OfflineQueue`, sender, dan trigger. `SignedInProviders` + `AccessGate` memutuskan tujuan: belum masuk ke `/login`, sesi habis ke pesan "Sesimu sudah berakhir", akses belum aktif ke `/access-status`, belum onboarding ke `/onboarding`.
2. `/login` dan `/auth/verify`: respons sama untuk semua email, satu pesan untuk kode salah, kirim ulang terkunci 60 detik, bantuan "Tidak menerima kode?" (spam, email checkout, kirim ulang, WhatsApp CS bila ada).
3. `/onboarding`: 3 layar (selamat datang, wilayah atau jadwal manual, konfirmasi Subuh) lalu dashboard. `completeOnboarding` dan `requestPersistentStorage` dipanggil di akhir.
4. `/access-status`: pembelian belum terverifikasi, atau belum ada akses. Tombol cek lagi, ganti email.
5. Counter memakai antrean: tap digabung reducer domain, tiap batch masuk antrean persisten, hitungan tampil = hitungan server + operasi di antrean + tap yang belum masuk. Setelah antrean kosong, hitungan server dibaca ulang. Operasi yang tersisa dari kunjungan sebelumnya dibangun ulang dari antrean. Catatan ditolak server tampil dengan tombol "Mengerti". `TODO(S4a)` sudah hilang dari kode.
6. Logout: `LogoutButton` memeriksa antrean (DZIKIR-06), menampilkan peringatan, "Sinkronkan dulu", catatan ditolak, atau "Tetap keluar dan hapus catatan". Keluar = hentikan trigger, akhiri sesi, hapus database user, kembali ke `/login`. Tombol ada di sidebar (desktop) dan di setiap `PageHeader` (ponsel).
7. `UpdatePrompt` di shell. Kartu "Pasang di layar utama" di dashboard membuka `InstallGuide`.
8. Dev panel masuk (`AuthDevPanel`) di layar masuk, onboarding, dan status akses: baca kode OTP, ubah hak akses email, muat skenario, majukan jam. Tombol "Majukan sesi login 31 hari" ditambah ke dev panel data.
9. Halaman `/` memiliki tombol Masuk dan mengarahkan pengunjung yang sudah masuk ke `/dashboard` (PRD §5.2).

## Belum diuji / risiko

- Antrean hanya diuji dengan mock di dalam browser. Tidak ada jaringan nyata: "offline" diuji lewat `context.setOffline` (peristiwa `online`/`offline` browser) dan lewat saklar offline tiruan.
- Checklist (centang salat) belum lewat antrean. `activity-row.tsx` masih memanggil layer langsung. Saat T3 menggantinya dengan HTTP, centang offline akan gagal. Perlu `checklist_set` di antrean.
- Sesi yang dicabut dari perangkat lain (`revoked`) kembali ke `/login` tanpa pesan. Hanya `expired` yang punya pesan.
- Reload saat offline di build tanpa service worker tidak bisa dimuat (halaman tidak tersimpan). Pemulihan antrean setelah reload diuji di tingkat unit.
- Login ke-4 mengeluarkan perangkat terlama (aturan S4a-10) di mock. Belum ada layar yang memberi tahu.
- Wake Lock dan getar tetap belum diuji di perangkat nyata.
- Tidak ada Delivery Gate formal.
